# 0015. Rules that came from running the real model: reply language, escalation as last resort, one call per tool

Status: accepted (amends [0006](0006-model-driven-router-loop-with-bounded-autonomy.md), [0011](0011-human-in-the-loop-with-leased-tickets.md), [0012](0012-layered-guardrails-and-untrusted-data.md), [0013](0013-semantic-evaluation-with-a-regression-gate.md))

Everything up to this point was verified with a scripted model and the offline policy. The first evaluation against the real model failed its gate (semantic pass 0.72, judge pass 0.78) and showed behaviours neither of those could show. Each became a rule enforced in code, because a sentence in a prompt had already failed to prevent it.

- Reply language. With evidence mostly in Portuguese, the model answered English questions in Portuguese in 24 of 29 cases, and the Critic let it through. The merchant's language is now detected in code from function words (English, Portuguese, Spanish), stated in the Router, Escalation and Critic prompts, and a draft in another language is sent back regardless of the Critic's verdict. The offline policy is extractive and cannot translate, so the hard rule applies only to model-written drafts; the evaluation reports language match as its own gated metric.
- Escalation is the last resort. Asked why a card machine would not connect, the Router escalated to a human because the same telemetry record carried an unrelated declined transaction that needs approval. Escalating pauses the turn, so the merchant got no troubleshooting steps at all. The Router now escalates for approval only when the fix for the problem that was asked about needs it, answers with self-service steps first when they exist, and mentions an unrelated finding instead of acting on it. The Support Agent reports such a finding as unrelated. The waiting message says what was found and why a human is involved, and it passes the output guard like any answer.
- One call per parameterless tool. The Support Agent called the same telemetry tool on every step until its budget ran out. A tool without parameters is now offered once; a repeated call is not executed and the next step can only report. Parallel tool calls are disabled so each decision is made after reading the previous result.
- The Critic fails to the deterministic checks. If no review comes back, unsupported numbers and unreturned URLs decide; silence is no longer an approval. It is also told that "could not confirm" is acceptable only after the right specialist was asked, which is what a compound question answered by one specialist looked like.
- Guardrail patterns were tightened after eight ordinary merchant questions out of eight were blocked ("cliente 30 dias" read as a merchant id, "todos os clientes" as bulk exfiltration, "merchant-specific" in an answer as a cross-tenant leak, which replaced a correct answer with a refusal in the evaluation). The benign control set grew from 8 to 30 and the attack set from 24 to 36, adding paraphrased, German, French and pretext attacks that the lexical layer does not catch and the classifier or the structure must.

The evaluation harness had its own defects, found the same way: evidence for the judge was cut at 12,000 characters, dropping the human decision the final answer reports; multi-turn questions were judged as one question; ticket ids counted as unsupported numbers; an item that ended parked on a human still counted as answered; and a gated metric that was never produced did not fail the gate. All are fixed, the judge rubric states that groundedness is measured against the evidence and that a refusal is not an answer, and each of those cases is now in the judge calibration set.

Two things were deliberately left alone. Latency: a turn is five to nine sequential model calls (classifier, Router, specialist tool loop, Critic); the measured p50 and p95 are in the evaluation report, and the bounds are the lever. And the judge still accepts an answer in another language as correct; language is measured separately so the two failures are not confused.
